# ask-draft — 실무자에게 보낼 메시지 초안

## 입력
- 지금의 고민 1개, 관련 맥락(DOMAIN/PLAN 항목), 원하는 유형

## 유형
| 유형 | 쓰는 때 | 형태 |
|---|---|---|
| 확인형 | 이해가 맞는지 | "~로 이해했는데 맞을까요?" |
| 선택형 | 두 갈래 중 선택 | 각 선택지가 실무자에게 주는 결과를 한 줄씩 → "어느 쪽이 편하실까요?" |
| 예외형 | 경계 사례 | "~한 경우에는 보통 어떻게 보세요?" |
| 범위 협상형 | 오늘 범위 합의 | "오늘은 ①②를 먼저, ③은 다음으로 두려는데 괜찮을까요?" |
| 중간 피드백형 | 만든 것 확인 | "지금 이렇게 동작하는데, 실제로 쓰실 때 빠진 게 있을까요?" |

## 작성 규칙
- 기술 용어를 업무 언어로 바꾼다 ("결측 행 drop" → "측정값이 빠진 데이터를 빼고").
- 한 메시지에 질문 1~2개, 5줄 이내: 맥락 한 줄 → 질문 → (선택형이면) 선택지별 영향.
- 동료에게 묻는 말투. 과한 정중체·긴 서론 금지.
- 해결책을 실무자에게 떠넘기지 않는다 ("어떻게 만들까요?" 대신 업무 기준을 묻는다).
- 초안은 짧은 버전과 자세한 버전 2개. 사람이 고쳐서 보낸다.

## 기록
- 보낸 메시지의 목적(어떤 결정에 쓰이나)을 INTERVIEW.md에, 답을 받으면 domain-notes와 DECISIONS.md에 연결한다.
