# right-size-audit — 적정 크기 감사

## 1. 오버엔지니어링 점검 (PLAN.md 범위와 대조)
- PLAN에 없는 기능, 화면, 설정, 옵션
- 요구에 비해 과한 구조: 쓰기가 없는데 쓰기 방어 로직, 소규모인데 DB·캐시·큐, 사용자 1명인데 인증·권한 체계
- 사용하지 않는 의존성, 죽은 코드, 한 번만 쓰이는 추상화
→ 목록을 보여주고 **사람이 제거 여부를 결정**한다. 제거한 것은 DECISIONS.md에 "무엇을 왜 걷어냈나"로 남긴다.

## 2. 문서-코드 대조
- README·PLAN·USER_GUIDE·DECISIONS에 적힌 기능·동작마다 실제 코드 위치(파일:함수)를 찾는다.
- 코드가 없으면 문서를 고치거나 "미구현"으로 표기한다. 부분 구현은 "부분 구현"으로.

## 3. 기본 품질
- 사용자 입력 검증, 비밀값·절대경로 하드코딩, 에러 메시지가 사용자에게 의미 있는지.

## 4. 마무리
- 수정 후 verify와 e2e-check L1을 다시 실행하고 커밋: `refactor: 범위 밖 코드 정리` / `docs: 문서-코드 일치`.
