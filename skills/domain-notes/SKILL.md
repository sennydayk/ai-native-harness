# domain-notes — 도메인 지식 누적

## 언제
- 실무자 답변을 받은 직후 매번. 입력은 답변 원문 또는 요약.

## 절차
1. DOMAIN.md가 없으면 `harness/templates/DOMAIN.md`를 루트에 복사한다.
2. 답변을 섹션에 배치한다: 용어 / 업무 흐름 / 판단 규칙·노하우 / 데이터의 의미 / 제약 / 미해결 질문.
3. 항목마다: 내용 — 출처(실무자 원문 짧은 인용, 시각) — 확신도(확인됨/추정) — 연결(PLAN·DECISIONS 항목, 아직 없으면 비움).
4. BRIEF.md의 "확인 필요" 용어가 확인되면 이곳으로 옮기고 BRIEF 상태를 갱신한다.
5. 새 답이 기존 항목과 **충돌하면 옛 항목을 지우지 않는다**: 취소선 + "대체됨(시각)" 표시 후 새 항목 추가 → ask-draft(확인형)로 재확인 질문을 만든다.
6. 설계에 영향을 주는 변화면 PLAN.md 변경 이력에 한 줄 남긴다.

## 규칙
- INTERVIEW.md는 시간순 대화 로그, DOMAIN.md는 주제별 최신 지식이다. 대화를 복붙하지 말고 정제해서 쓴다.
- 실무자가 말하지 않은 것을 사실로 쓰지 않는다. 에이전트가 보충한 일반 지식은 "추정"으로 표시한다.
- 짧게 유지한다. 구현 시에는 필요한 섹션만 읽는다.
