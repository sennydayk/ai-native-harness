# discovery — 실무자 인터뷰

## 전제
- 실무자는 요구를 한 번에 알려주지 않는다. 업무 방식을 물으면 답하지만 해결책은 알려주지 않는다.
- 질문하는 과정 자체가 평가된다. 사소한 맥락 질문부터 시작해 점점 구체화한다.

## 사다리 (한 메시지에 질문 1~2개)
1. 맥락: 어떤 일을 맡고 계신지, 하루 업무 흐름
2. 현재 방식: 지금은 어떤 순서·도구로 하는지, 가장 오래 걸리는 단계
3. 판단 기준·노하우: 무엇을 보고 판단하는지, 기준값, 신입에게 어떻게 가르치는지
4. 사례: 최근 문제가 됐던 구체적 사례 하나
5. 사용자·결과: 결과를 누가 언제 무엇에 쓰는지, "잘 됐다"의 기준
6. 제약: 보안·권한, 데이터, 사용 환경
7. 우선순위: 오늘 꼭 필요한 하나
8. 합의: 이해한 내용 요약 → 맞는지 확인 (spec-agree로 이어짐)

## 기록
- 답을 받을 때마다 `INTERVIEW.md`(templates 복사)에 한 줄: 시각 / 질문(목적) / 답변 요지 / 분류 / 반영 위치.
- 분류: **명시 요구**(직접 말한 기능), **숨은 요구**(말하지 않았지만 필요한 것), **노하우·판단 기준**(서비스에 녹일 규칙), **제약**.
- 지식은 domain-notes로 DOMAIN.md에 누적한다.

## 규칙
- 실무자가 쓴 용어·기준값·순서는 바꾸지 않고 그대로 받아 적는다.
- 답이 README와 다르면 어느 쪽을 따를지 다시 묻는다.
- 막히면 "어떤 것들을 여쭤보면 될까요?"는 허용된다.
- 발굴은 전체 시간의 20% 안팎에서 끊고, 남은 질문은 구현 중 ask-draft로 짧게 묻는다.
