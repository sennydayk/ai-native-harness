# risks — 리스크 정리

## 절차
1. 코드·DOMAIN·EXPLORE·E2E_RESULT를 근거로 약점 3~6개를 찾는다:
   - 데이터: 형식 변화, 결측, 규모 증가
   - 로직: 판단 규칙의 임계값·가정이 틀릴 때, 오탐·누락
   - 운영: 서버 장애, 의존성, 설정
   - 보안·권한
2. 각각 **구체적 위치(파일:함수) → 파급(사용자에게 무슨 일) → 대응(지금 해 둔 것 / 다음 검증·개선)** 으로 쓴다.
3. "장애가 나면" 섹션: 증상 → 먼저 확인할 것 → 복구 방법.
4. 지금 바로 고칠 수 있는 작은 것(예: 실패 건수 표시)은 사람에게 제안한다.

## 규칙
- 일반론("보안에 유의") 금지. 이 코드의 이 부분에 대한 구체적 위험만.
- 실무자가 말한 기준(DOMAIN)이 바뀌면 생길 일을 반드시 하나 포함한다.
