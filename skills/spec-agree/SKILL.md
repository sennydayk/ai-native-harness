# spec-agree — 요구 정리와 합의

## 절차
1. `harness/templates/PLAN.md`를 루트에 복사한다. BRIEF의 제출 체크리스트를 맨 위로 옮긴다.
2. DOMAIN.md·INTERVIEW.md를 근거로 채운다:
   - 목표 한 줄, 사용자와 핵심 시나리오
   - **서비스에 녹일 판단 규칙·노하우** (실무자 표현 그대로)
   - 범위: MVP(남은 시간의 60% 안에 끝낼 수 있는 크기) / 확장 / **제외와 그 이유**
   - 성공 기준: 실무자가 "됐다"고 할 구체적 조건 (가능하면 사례나 숫자)
   - 데이터 처리 기준, 검증 방법
3. ask-draft(범위 협상형 + 확인형)로 요약 메시지를 만든다 → 사람이 다듬어 보낸다.
4. 답을 반영해 PLAN을 고치고 "변경 이력"에 남긴다 → 커밋 `docs: 실무자 합의 반영`.
5. AGENTS.md가 루트에 있는지 확인한다.

## 규칙
- MVP는 작게. 범위 밖 요청은 "제외(이유)" 또는 "확장"으로 명시해 둔다.
- 실무자 확인 전에 구현하지 않는다. 답이 늦으면 확인 질문을 보낸 상태로 design-options까지만 진행한다.
- 요구가 바뀌면 PLAN을 갱신한다 (의도 갱신의 기록).
