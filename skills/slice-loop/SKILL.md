# slice-loop — 기능 단위 구현 루프

## 순서
1. **최소 E2E 먼저**: 서버가 뜨고(0.0.0.0) 화면에 실제 데이터가 한 번 흐르는 것. 그다음 기능을 하나씩 붙인다.
2. PLAN.md의 MVP를 3~6개 slice로 나눈다. 각 slice는 30분 이내.

## slice 하나의 루프
1. **지시 4요소**를 명확히: 목표 / 입력·위치 / 제약(PLAN·DOMAIN 규칙, 새 의존성 금지 등) / 완료 조건(확인 방법)
2. 계획 3줄 → 사람 확인 → 구현 (최소 diff)
3. 실행: 명령과 출력을 보여준다
4. verify 스킬로 검증 (테스트 실행, 값 대조)
5. 화면이 바뀌었으면 e2e-check L1 재실행
6. 커밋: `feat: <slice> — <의도>` (한 slice = 한 커밋 이상)
7. 판단이 있었으면 DECISIONS.md 한 줄

## 위임
- 화면 작업처럼 길고 독립적인 slice는 별도 터미널의 별도 세션에 범위·파일·완료 조건을 명확히 주고 맡긴다. 메인 세션은 설계·검증을 맡는다.
- 같은 파일을 두 세션이 동시에 고치지 않는다. 에디터에서도 에이전트가 수정 중인 파일은 편집하지 않는다.

## 멈춤 규칙
- 같은 문제로 2번 연속 실패 → 요청을 더 작게 쪼개거나 `third_party/systematic-debugging`
- 한 이슈에 10분 이상 → 우회·범위 축소 후 DECISIONS에 기록
- 전체 시간의 50% 시점에 핵심 흐름이 안 돌면 확장 포기
- 남은 시간 30분 이하 → 새 기능 금지
- 세션이 무거워지면 handoff(세션 모드)
